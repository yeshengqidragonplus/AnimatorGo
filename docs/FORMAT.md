# 格式规范

**这份文档是编辑器与所有运行时之间的共同契约。** 任何一处约定在某个运行时上理解错了,症状都是「动画看着有点怪但说不出哪里怪」——不崩溃、不报错、很难查。

---

## 1. 必须固定的约定

以下是编辑器内部的约定。**各引擎的差异在导出时转换,运行时不做任何转换。**

| 约定 | 取值 |
|---|---|
| **Y 轴** | 编辑器内部 **Y 向上**。Godot 2D 的 Y 朝下,由导出器翻转数据 |
| **旋转** | **逆时针为正**,单位 **度**(不是弧度) |
| **矩阵** | **列主序、列向量**(`M * v`) |
| **变换顺序** | **缩放 → 旋转 → 平移**(`T * R * S`) |
| **关键帧语义** | **相对绑定姿势(setup pose)的偏移**,不是绝对值 |
| **颜色 / Alpha** | **线性工作流,非预乘**。见下方第 1.2 节 |
| **时间** | 秒,浮点 |
| **UV 原点** | 左上角 |

### 1.2 色彩空间:线性工作流,不做可配置转换

**统一走线性工作流,不提供色彩空间选项。** 三个目标引擎都支持,不需要为此做配置系统。

具体是这样分工的 —— 这是标准做法,别自己发明:

| 环节 | 怎么处理 |
|---|---|
| 切图 PNG | 美术软件输出的就是 **sRGB 编码**,原样使用,导入时不做任何转换 |
| 纹理采样 | 引擎侧把图集标记为 **sRGB 纹理**,由**硬件**在采样时转成线性 |
| 混合与光照计算 | 在**线性空间**进行 |
| 顶点色 / slot tint | 按 sRGB 数值书写(如 `ffffffff`),着色器采样时转线性 |
| 最终输出 | 引擎负责转回 sRGB 显示 |

**关键点:转换由硬件和引擎完成,本工具不做任何色彩空间数学。** 导出器只需要在各引擎的
资源配置里把图集标成 sRGB 纹理:

- **Godot** —— 默认即线性渲染,纹理导入设置里勾 sRGB
- **Unity** —— Project Settings 里 Color Space 设为 **Linear**(不是 Gamma)
- **Cocos Creator** —— 纹理默认按 sRGB 处理

**Alpha 一律非预乘。** 预乘 alpha 已评估否决:它能改善缩放时的边缘渗色,
但要求整条管线(打包器、着色器、混合模式)全部配套,对本工具的收益不值这个复杂度。

### 关于「关键帧是相对绑定姿势的偏移」

这一条最容易搞错,单独说明。

数据文件里的 `bones` 记录的是**绑定姿势**。动画时间轴里的 `rotate: 30` 意思是「在绑定姿势的基础上再转 30°」,不是「转到 30°」。

```
最终值 = 绑定姿势值 + 动画关键帧值        (translate / rotate)
最终值 = 绑定姿势值 × 动画关键帧值        (scale)
```

注意 scale 是**乘**不是加。

## 2. 数据模型:Bone / Slot / Attachment 三层分离

```
Bone        只管变换,构成树
Slot        只管绘制顺序 + 当前挂哪个 attachment + 颜色
Attachment  实际的图(region / mesh / boundingbox)
```

**这三层不能合并。** 原因:

1. 动画中要能**换图** —— 眨眼、换武器、换表情。所以「挂什么图」必须是可以打关键帧的属性,不能焊死在骨骼上
2. **绘制顺序必须独立于骨骼层级** —— 角色转身时,手要从身前绕到身后,但骨骼层级完全没变

一层做不到,两层也做不到。

### Bone

```jsonc
{
  "name": "arm_upper",
  "parent": "torso",        // 根骨骼无此字段
  "x": 10, "y": 30,         // 相对父骨骼
  "rotation": 15,           // 度,逆时针为正
  "scaleX": 1, "scaleY": 1,
  "shearX": 0, "shearY": 0,
  "length": 80,             // 仅用于编辑器显示
  "inheritRotation": true,  // ⚠️ 见下方「缩放继承」
  "inheritScale": true
}
```

**⚠️ 缩放继承**:非均匀缩放 + 旋转在层级中传递会产生错切(shearing),看起来像被斜着拉过。`inheritRotation` / `inheritScale` 用于关掉这个传递。

代价:三个引擎的节点层级都是完整继承,没有这两个开关。**一旦某根骨骼用了非默认值,它就无法映射到引擎原生层级** —— 走运行时路线没问题(运行时自己算),但如果将来要做原生导出降级方案,这些骨骼得烘焙成世界变换。

### Slot

```jsonc
{
  "name": "hand",
  "bone": "arm_lower",        // 跟随哪根骨骼
  "attachment": "fist",       // 绑定姿势下挂哪个 attachment,null 表示不显示
  "color": "ffffffff",        // RGBA,sRGB 非预乘
  "blend": "normal"           // normal | additive | multiply | screen
}
```

`slots` 数组的**顺序就是默认绘制顺序**(先画的在下层)。

### Attachment

三种类型:

```jsonc
// region —— 一张不变形的图
{
  "type": "region",
  "path": "head",             // 图集中的名字,缺省用 attachment 名
  "x": 0, "y": 0,             // 相对 slot 所属骨骼
  "rotation": 0,
  "scaleX": 1, "scaleY": 1,
  "width": 128, "height": 152 // 原始尺寸(未裁剪的)
}

// mesh —— 可形变的网格
{
  "type": "mesh",
  "path": "cloak",
  "uvs": [...],               // 每顶点 2 个 float
  "triangles": [...],         // 每三角形 3 个索引
  "vertices": [...],          // 见下方「mesh 顶点编码」
  "hull": 12,                 // 前 12 个顶点构成外轮廓,其余是内部顶点
  "edges": [...]              // 供编辑器显示用
}

// boundingbox —— 碰撞/命中框,不渲染
{
  "type": "boundingbox",
  "vertexCount": 4,
  "vertices": [...]
}
```

#### mesh 顶点编码

未绑定骨骼时,`vertices` 就是 `[x0, y0, x1, y1, ...]`。

绑定骨骼后改为变长编码,每个顶点:

```
[骨骼数 n, 骨骼索引0, x0, y0, 权重0, 骨骼索引1, x1, y1, 权重1, ... ]
```

其中 `xi, yi` 是该顶点在第 i 根骨骼**局部空间**下的坐标。运行时求值:

```
v = Σ (权重ᵢ × 骨骼ᵢ的世界矩阵 × (xᵢ, yᵢ))
```

权重之和应为 1。

## 3. 图集

两个文件:`xxx.png`(打包后的大图)+ `xxx.atlas`(文本描述)。

```
character.png
size: 1024,1024
filter: Linear,Linear
head
  bounds: 2,2,120,140
  offsets: 4,6,128,152
  rotate: false
arm_upper
  bounds: 124,2,60,90
  offsets: 0,0,60,90
  rotate: true
```

### 两个必须处理的坑

**`rotate`** —— 打包器会把切图旋转 90° 塞进缝隙以提高利用率。运行时必须把 UV 转回来,否则那张图是躺着的。

**`offsets`** —— 打包时会裁掉透明边省空间。格式为 `offsetX, offsetY, originalWidth, originalHeight`。

必须同时记录**原始尺寸**和**裁剪偏移**,否则所有切图的锚点都会偏,而且偏移量取决于每张图各自被裁掉多少,**毫无规律**,极难 debug。

打包算法:**MaxRects**(JS 用 `maxrects-packer`)。

## 4. 动画

```jsonc
{
  "animations": {
    "walk": {
      "bones": {
        "arm_upper": {
          "rotate":    [ { "time": 0, "value": 0, "curve": "linear" },
                         { "time": 0.5, "value": 30 } ],
          "translate": [ { "time": 0, "x": 0, "y": 0 } ],
          "scale":     [ ... ],
          "shear":     [ ... ]
        }
      },
      "slots": {
        "hand": {
          "attachment": [ { "time": 0.3, "name": "open" } ],   // 离散,不插值
          "color":      [ { "time": 0, "color": "ffffffff" } ]
        }
      },
      "deform": {                       // 网格顶点形变
        "default": {                    // 皮肤名
          "cloak": {
            "cloak": [ { "time": 0, "offset": 0, "vertices": [...] } ]
          }
        }
      },
      "drawOrder": [                    // 离散,不插值
        { "time": 0.5, "offsets": [ { "slot": "hand", "offset": -2 } ] }
      ],
      "ik": [
        { "time": 0, "mix": 1, "bendPositive": true }
      ]
    }
  }
}
```

### 曲线

`curve` 字段:

- `"linear"`(缺省)
- `"stepped"` —— 保持前值直到下一帧
- `[cx1, cy1, cx2, cy2]` —— 三次贝塞尔控制点

贝塞尔求值需要按 x 反解 t。做法:预先烘焙成查找表,不要每帧解方程。

## 5. 动画融合

融合的难点不是「两个姿势按比例混合」,是下面三条。**每一条都必须在所有运行时上行为一致。**

### ① 「没有关键帧」≠「值为 0」

动画 A 给手臂打了关键帧,动画 B 没有。从 A 淡出到 B 时,手臂**必须混合回绑定姿势**,而不是卡在 A 的最后一帧。

这要求运行时记录每个动画**碰过哪些时间轴**,对没碰过的骨骼单独往绑定姿势方向混合。

**这是「角色胳膊卡住不动」类 bug 的头号来源。**

### ② 离散属性无法插值

`attachment` 和 `drawOrder` 是离散的 —— 不存在「50% 握拳 + 50% 张手」。

**规则:权重 ≥ 0.5 时切换到新值,否则保持旧值。** 这条规则必须在所有运行时上一致。

### ③ 旋转走最短路径

`350° → 10°` 必须走 `+20°`,不能走 `-340°`。

混合多个动画时同样适用。实现:把差值规范化到 `(-180, 180]`。

## 6. 约束求解顺序

约束必须在骨骼世界变换算完之后解算,且**顺序固定**,否则结果不确定。

数据文件中约束按 `order` 字段排序,运行时严格按此顺序解算。一个约束解算完后,受影响骨骼的世界变换要立即更新,再解下一个。

### IK 约束

```jsonc
{
  "name": "leg_ik",
  "order": 0,
  "bones": ["thigh", "shin"],   // 1 根 = 单骨,2 根 = 两骨闭式解,>2 = FABRIK
  "target": "foot_ctrl",
  "mix": 1,                      // 0..1,支持淡入淡出
  "bendPositive": true,          // ⚠️ 弯曲方向
  "softness": 0                  // 接近极限时的软衰减,避免绷直时的机械感
}
```

**`bendPositive`** —— 两骨 IK 有两个解(肘朝上 / 朝下)。此标志选择其一。中途翻转会导致爆闪,所以它可以打关键帧但应谨慎使用。
